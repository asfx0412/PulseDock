# PulseDock 6.14.0 使用文档

PulseDock 是一个“面向 AI 开发者的轻量工作状态浮窗”。它把 Codex 额度、AI 网络诊断、Clash 用量、多 SSH/GPU、温度与热风险、应用活跃度、番茄钟、工作日历、飞书告警与专注声音放在同一个低干扰窗口中。

6.14.0 的原则是：额度来源由用户决定是否显示在工作台，小窗口只置顶一个 API/Codex 来源，并独立保留 Clash 剩余额度；所有额度在每次启动主动解锁保险库后才读取。公网出口仅作网络观察，不会替代天气地点或局域网范围。数据源短暂失败会保留最后成功值并自动重试，不要求用户反复手动刷新。

## 1. 安装、升级与退出

1. 解压 `PulseDock-6.14.0.zip`。
2. 将 `PulseDock.app` 拖到“应用程序”。
3. 首次运行若 macOS 提示无法验证开发者，右键应用选择“打开”。
4. 需要番茄钟、下班与热风险提醒时，允许通知权限。

当前安装包面向 Apple Silicon 与 macOS 26，使用 ad-hoc 本地签名，没有 Developer ID 公证。自动更新会验证 GitHub Release 清单签名、ZIP SHA-256、应用身份、版本、arm64 与代码签名；首次启动仍可能需要按 macOS 的 Gatekeeper 提示确认。

升级前请先完全退出旧版，再替换 `PulseDock.app`。旧进程已经排队的 macOS 钥匙串密码框无法被新进程撤销。

退出方式：

- 浮窗右键 →“退出 PulseDock”；
- 菜单栏入口 →“退出”；
- 展开面板的窗口菜单中退出。

关闭浮窗不等于退出。“收起到菜单栏”和“收起到程序坞”都会保留后台监控。

## 2. 浮窗的展开、拖动与收起

- 双击仅在窗口外侧真正的空白边缘或显式拖动把手生效：紧凑态展开，完整态收起。完整内容画布内的按钮、开关、菜单、滑杆、分页、卡片操作、滚动和输入框会优先接收双击，不会被误判为收起动作；左上角手势图标仍是可发现的拖动/双击入口。
- 默认全局快捷键：`⌥ Space` 显示/隐藏，`⌥ ⇧ Space` 展开/收起。隐藏时按显示快捷键召唤小窗，按展开快捷键直接召唤完整窗口；可在设置中改选，冲突时会显示注册错误。
- 在紧凑态或完整态，按住任意非交互背景并移动超过约 4 pt 即可拖动窗口。左侧手势图标仍是可发现的备用拖动点，不是唯一拖动区。
- 按钮、输入框、可选文本、Slider、菜单、链接和滚动条优先保留原生操作，不触发拖动或双击切换。
- 右键可设置透明度、“只在当前桌面显示”、收起到菜单栏/程序坞与退出。

“只在当前桌面显示”的“桌面”指 macOS Mission Control 的 Space，不是当前网页。

菜单栏图标被其他图标挤压时，可在设置中点击“修复菜单栏入口”。再次在 Finder 打开 PulseDock 不会启动第二个实例，而是唤回已运行的浮窗。

## 3. 完整面板的七个页面

### 3.1 工作台

显示工作/午休/下班/加班状态、当前应用、今日第一名、番茄钟、天气、AI 网络、Codex/Clash 和系统指标。紧凑浮窗只显示最需处理的异常。

Codex 紧凑值按所有官方窗口中的“最低剩余”计算，因此不会在 5 小时额度充足时漏掉已经紧张的周额度。

平衡小窗口可同时显示一个用户置顶的 API/Codex 剩余额度与 Clash 剩余流量；两者是独立指标，Clash 不占置顶名额。保险库未解锁时不会读取或显示这些额度。

### 3.2 洞察

包含应用活跃排行榜、Codex 官方额度/重置券、14 日 Token 活动、社区全局重置信号、天气和节假日。

### 3.3 设备

管理多台 SSH 设备，查看 SSH 状态、Load、总显存、GPU 矩阵、温度/功耗、Codex 发现、端点证据、Slurm 任务或用户明确允许的脱敏启动命令。

### 3.4 时间线

统一记录网络、远程设备、额度、热风险、Clash 和番茄钟的“发生、证据、恢复、持续时间”。首屏懒加载，需要时再继续加载旧事件。

### 3.5 诊断

按 DNS、代理端口、TLS、OpenAI/Codex 端点、规则路由、普通网络对照等分层诊断。普通 TLS、ChatGPT 与 OpenAI API 会执行三轮低频采样，并显示中位数、范围和可达轮数；单次冷连接不会直接触发换节点建议。可复制报告，但报告不包含 API Key、密码或未脱敏启动命令。

6.8.0 新增“界面响应监测”，显示主线程延迟 P95、P99、最大值、超过 500 ms 的次数和最近系统指标采样耗时。如果“按钮等一阵才能点”再次出现，请先保留这组数值，它能区分主线程停顿与网络请求/控件状态问题。监测不记录点击坐标、键盘内容、窗口标题或文件名。

### 3.6 设置

设置工作时间/午休/工作日、活跃度、天气、番茄钟、Clash/Mihomo、飞书、API 额度连接器、SSH 任务隐私、主题、透明度、紧凑密度、语言与安全凭据。

### 3.7 声音

分为环境音、工作音乐和网络广播。三类共用一个播放器，同时最多播放一条音频流，且都使用 **2 列 × 3 行、每页 6 条** 的目录布局；每类都有发现、搜索、网络模式、收藏和分页。环境音内置 24 条互不重复、已核验作品页、CC0 许可和 HTTPS 播放链接的录音，共 4 页；不会使用重复或来源不明声音凑数量。

三种播放器外框尺寸一致但视觉语义不同：环境音是低刷新率的程序化动态声景，工作音乐是磁带机，网络广播是收音机。6.9.0 的环境声景按已审核的录音类型分别绘制：窗边雨、城市晚雨、雷雨、海浪、溪流、森林、壁炉、暖炉、咖啡馆、书桌、列车与夜景不会再共用同一段频谱动画；抽象频谱只用于棕色噪音。环境场景不是下载的视频；暂停或系统开启“减少动态效果”时自动降为静态，避免额外功耗。

控制方式：上一条、播放/暂停、停止、下一条均为图标按钮并带有悬停说明；定时胶囊单击依次为关闭/15/30/60 分钟，右键可选择常用值或设置 1–240 分钟。播放模式以一个图标表示，单击依次切换顺序循环、随机、单条循环，右键可查看完整文字。播放模式始终作用于当前实际播放队列，不会因浏览另一个标签而意外改变。

分页无需先获取全部音频：相邻数字页、前后 1/2 页以及手动输入页码，都会按页换算为第三方目录 offset，仅请求该页附近的有限候选。目录不提供可靠总数时，PulseDock 不伪造“共多少页”。

环境音“发现”中的类型筛选是内容宽度的紧凑标签：会按窗口宽度自动换行，不会将每个标签拉成半屏长条；“全部”可随时清除筛选。

搜索框以及远程设备、天气、API、Mihomo 的普通文本输入均使用原生 macOS 编辑器，支持简体拼音 marked text、可见光标、系统活动选区、`⌘A/C/X/V/Z` 与回车提交。若第一次点击没有光标，请先确认打开的是 6.10.0，而不是仍运行的旧进程；若仍有问题，请复制“诊断”页的“界面响应监测”信息并附上输入法名称与复现步骤。

“当前出口”首屏显示国家和城市，并以“经系统代理观测”或“直连观测”说明本次查询路径。展开“查看出口详情”可查看和复制 IPv4/IPv6 地址、完整归属、网络提供方与查询时间。该卡只观察网络出口，不会参与天气城市、自动定位或局域网设备判断。

音量区域为固定宽度：左侧扬声器按钮用于静音/恢复，右侧滑杆范围为 0–80%。切换静音、音量图标或拖动滑杆不应移动定时器、循环按钮或改变窗口尺寸。

音频网络模式：

- **智能兼容（推荐）**：先跟随系统/Clash；连续缓冲约 9 秒后，只为当前公共 HTTPS MP3/AAC 流尝试本机直连中转。
- **跟随系统**：严格使用系统网络，不做直连回退。
- **仅直连**：只让 PulseDock 当前音频绕过系统代理；不影响浏览器和其他应用。

点击网络音频后先执行最多约 7 秒的首包预检，只读取首个响应字节，不建立离线文件。失败会按 TLS/证书、DNS、连接、首包超时、直播流中断、格式和源站 HTTP 分类；失败来源在本次网络会话中冷却 5 分钟并排到后面，用户仍可主动重试。成功来源会优先显示。

播放器会显示“系统路由”或“智能直连”。本机中转停止、换台或退出即关闭；HLS 暂不直连改写，失败时会明确提示而不是无限缓冲。

## 4. Codex 额度、Token 活动与社区信号

PulseDock 启动短生命周期的本机 `codex app-server`，只读请求：

- `account/rateLimits/read`：个人额度窗口、已用/剩余、完整刷新日期、官方重置券；
- `account/usage/read`：Token 累计摘要和每日活动。

额度与 Token 活动独立降级：旧版 app-server 不支持 usage 时，额度仍可正常显示。PulseDock 不读取、刷新或导出 Codex 登录 Token，不消耗重置券。

默认每 5 分钟自动读取，也可手动刷新。同时刷新只会复用一次 app-server 查询，不会并发启动多个实例。

“社区全局重置信号”来自 Codex Runway 公共状态 JSON，是第三方信息，不是 OpenAI 承诺，也不参与个人额度计算。没有明确计划时就显示“暂无重置计划”，不推测。

## 5. API 额度连接器

支持：

- GLM Coding Plan 官方用量；
- DeepSeek 官方账户余额；
- Cursor 本地登录会话（实验性内部接口）；
- 官方 HTTPS 端点公开的 Rate Limit 响应头。

GLM 的多周期额度使用独立卡片显示窗口名、弱化的“窗口 1/2”、已用、剩余和刷新时间，不再拼成容易误读的 `#1 1%`。

每个连接器有两个独立选项：“在工作台显示”可多选；“置顶到小窗口”严格单选。切换小窗口置顶时会自动取消上一个来源，不显示 `+N`。Cursor 的紧凑摘要只显示综合剩余百分比，Auto、指定模型和金额留在展开详情。

API Key 只保存在 macOS Keychain 的 PulseDock 统一保险库，不进入 UserDefaults、时间线、报告或配置导出。

## 6. Clash 订阅与 Mihomo 控制器

Clash 用量优先读取 Clash Verge/Mihomo 本机已保存的兼容订阅元数据，不打开机场网页，不读取订阅 URL 或 Token。6.7.0 同时显示“已用、剩余、总计、百分比、数据更新时间”，避免与 Clash Verge 卡片的“已用 / 总量”混淆。例如客户端显示已用 80.9 GiB / 总量 1024 GiB 时，PulseDock 的约 943.1 GiB 是同一订阅的剩余量。

Mihomo External Controller 是可选的“让运行内核刷新 provider 后再重读本地用量”通道。6.6.0 会优先验证 Clash Verge 的本机 Unix Socket；这类运行方式不需要用户额外打开 9090：

1. 在 Clash Verge 运行配置中启用 `external-controller`。
2. 确认运行中的内核已重载配置，不是只编辑了 YAML。
3. 在 PulseDock 点“自动发现”；若没有发现 Unix Socket，再输入实际监听的 `127.0.0.1:<端口>`。
4. 有 Secret 时在统一保险库解锁后填写。
5. 先验证 `/version`，再同步 provider。

“配置写了 9090”不等于“运行内核正在监听 9090”。“无进程监听”时请先在 Clash Verge 重启/重载内核。控制器失败不会清空已读取的本地用量；Unix Socket 也只用于当前本机 Clash Verge，不开放局域网。

## 7. 多 SSH、GPU 与任务隐私

### 7.1 前置条件

PulseDock 复用本机 `~/.ssh/config`、系统 `ssh` 和 ssh-agent，输入的是 `Host` 别名，不是中文备注。添加前先在终端运行：

```sh
ssh <别名>
```

PulseDock 使用 `BatchMode=yes`，不在后台弹出远程密码框。终端可以登录、PulseDock 认证失败时，常见原因是终端使用了密码/交互式密钥，或 GUI 进程没有获得同一 `SSH_AUTH_SOCK`。诊断会建议使用 `ssh -v` 与 `ssh -G`，但不会自动改写密钥、`authorized_keys` 或 shell 配置。

### 7.2 采集与展示

- 最多同时探测 3 台设备；
- stdout/stderr 在进程运行时持续排空并限长；
- 显存是主指标，GPU 利用率、温度和功耗是辅助字段；N/A 会显示未知，不伪装成 0%；
- 重复 GPU/PID/Slurm job 安全去重，越界数值会被拒绝或夹紧并留下证据；
- 远程登录 shell 不是 POSIX shell 时，固定脚本仍通过 `/bin/sh` 执行。

默认任务模式是“仅 Slurm/调度器任务”，且只在用户打开对应采集开关时读取。“显示脱敏启动命令”会读取 GPU 进程参数，遮罩 Token/API Key/Secret/Password/Authorization、URL 机密查询参数和用户目录。这是最大努力脱敏，所以默认不开启。

### 7.3 网络范围与告警降噪

每台设备可标注“自动判断、仅局域网、需要 VPN、公网可达”，设备卡会显示对应的范围图标和文字。

“仅局域网”会先用 `ssh -G <别名>` 只读展开本机 SSH 配置中的实际 `HostName`，然后比较目标私有 IPv4 与 Mac 当前活动物理接口的私有 IPv4/子网。目标属于当前子网时才尝试 SSH；不属于、当前没有私网地址或本地 DNS 无法解析时显示灰色“当前网络暂停”。这种暂停不进入首页红色主状态、不计入失败次数，也不发飞书。判断不使用 Clash 出口公网 IP，不会因代理节点在国内或海外而变化。

“公网可达”只要系统有网络就持续探测；失败达到阈值后才告警。“需要 VPN”仅在系统检测到 VPN 隧道时探测。“自动判断”保留通用行为，若设备明确只在公司/家庭局域网使用，建议手动选“仅局域网”。不同地点可能恰好使用相同私网网段；macOS 在不额外读取 Wi-Fi 标识的前提下无法绝对区分这种碰撞，此时请使用 VPN 范围或手动暂停该设备。

系统观察到网络路径变化后有 90 秒宽限。宽限外连续 3 次失败才建立异常事件，真正健康后才记录恢复。macOS 不保证每次“Wi-Fi 换到另一个 Wi-Fi”都产生可区分的路径回调；本版不声称识别了所有 SSID。

设备支持置顶、上移、下移、立即刷新、复制诊断和 2 分钟观察。最多同时展开 4 台；删除已展开设备会同步释放展开名额。

## 8. 专注声音：环境音、工作音乐和广播

### 8.1 环境音

24 条固定 Freesound CC0 录音，覆盖雨、海浪、溪流、森林鸟鸣、夜虫、壁炉、咖啡馆、图书馆、键盘、列车、城市夜景和专注底噪等方向。每条都保存作者、Freesound source ID、作品页、许可页、标签、时长与最后核验日期；应用内可打开作品页，完整审计清单见项目根目录 `AMBIENT_SOUND_CATALOG.md`。

### 8.2 工作音乐

选择 Lo-fi、氛围器乐、轻爵士或古典专注场景，或搜索 Radio Browser 公开目录。本版的“工作音乐”是第三方网络直播流，不是点播音乐库。选中后显示复古磁带机；只有真正播放时才以低频率转动卷轴，暂停时不持续重绘。

### 8.3 网络广播

可选新闻、谈话、文化、世界电台或搜索台名。老式收音机的灯条是“播放状态灯”，不是伪造的 FM 信号强度。

目录最多返回 30 条，只接受 HTTPS MP3/AAC/HLS，拒绝 HTTP、本机/内网地址、URL 内带用户密码、失效台和重复 UUID/URL。

### 8.4 播放与隐私

- 默认不播放，不恢复上次音源；
- 选目录/搜索只请求元数据，点击播放才连接音频；
- 支持收藏、上一条/下一条、暂停、重试、停止、音量和 15/30/60 分钟定时；
- 本机只保存收藏 station ID，不保存播放历史、账号、Cookie 或离线音频；
- 查询词会发往 Radio Browser，播放时音频运营方会收到正常网络请求并可看到公网出口 IP；
- Radio Browser 是目录，不授予各电台节目的版权或地区许可。

本版没有接入 Apple Music、Spotify、QQ 音乐或网易云账号，也没有歌词。

## 9. 天气、定位、日出日落与月相

天气支持“固定地点”和“自动跟随当前位置”。固定地点是默认模式；手动选择城市、区县或镇会切回固定地点。自动跟随只有在用户主动开启并授权 Core Location 后工作，不根据公网 IP 或 Clash 节点变化。

自动跟随在窗口活跃时最多每 30 分钟检查一次，隐藏静置时最多每 2 小时一次，重新显示窗口时可立即检查。移动不足约 2 公里或行政区没有变化时不更新地址；定位失败保留最后有效地点与天气。卡片优先显示区/县/镇（若服务返回）、城市、省和国家，仅持久化当前天气点和上次检查时间，不保存位置轨迹。

显示温度、体感、降雨概率、风速、日出/日落和月相。默认约 30 分钟更新。

## 10. 应用活跃度、工作日与番茄钟

活跃度只记录普通前台应用的 bundle ID/名称、前台时长和有效使用时长。不读取窗口标题、网页、聊天、键盘内容或文件。锁屏、睡眠、合盖和超过空闲阈值不累计。

排行榜可看今日/7 天/30 天，紧凑窗默认显示今日第一名。误排除应用后可在设置恢复或“恢复全部”。

工作时间支持上班/下班、午休、每周工作日、中国法定节假日/调休、跨夜班次和当日人工覆盖。加班状态每日 00:00 自动清除。

番茄钟支持自定义专注、短休息、长休息和“每 N 轮长休息”，统计完成数、跳过数与今日专注时长。系统睡眠后根据绝对截止时间校正，不把计时器冻结。

## 11. 飞书告警

1. 在飞书群中打开“群设置 → 群机器人 → 添加机器人 → 自定义机器人”。
2. 复制 Webhook；若启用签名校验，同时复制签名密钥。
3. 在 PulseDock “设置 → 凭据保险库”主动解锁一次。
4. 在飞书卡填写 Webhook/签名密钥，点“保存全部变更”。
5. 点“发送测试”，群内出现“PulseDock · 连接测试”即正常。

只在异常首次触发和恢复时发送，同类告警有冷却。局域网/VPN 条件不满足时的 `expectedOffline` 不发送。

## 12. 统一凭据保险库

- 启动、切页和后台刷新不主动读 Keychain。
- 点“解锁凭据”后，本次运行只主动访问一次统一保险库；Codex、Cursor、Clash、飞书和 API 连接器在内存共享。解锁前所有个人额度与本地订阅额度均不读取、不显示。
- 输入过程不逐字符写 Keychain；点“保存全部变更”时写入。
- 退出 PulseDock 后内存凭据清空。

若仍连续出现“PulseDock 想要使用你储存在钥匙串中的机密信息”：

1. 完全退出所有旧 PulseDock 进程；
2. 打开“钥匙串访问”，搜索 `com.pulsedock.monitor`；
3. 只删除确认属于 PulseDock 的旧临时签名项，再启动 6.5.0 并重新保存一次；
4. 不要删除其他应用的钥匙串项。

| 数据 | 默认节奏 |
|---|---:|
| CPU/内存/温度/网速 | 约 2 秒 |
| 网络延迟 | 约 8 秒 |

## 14. 常见故障排查

### Cursor 一直显示未解锁

Cursor 卡不依赖 PulseDock API Key，但受 macOS 对 Cursor 本地数据库访问权限影响。请确认 Cursor 已登录并启动过，再手动刷新。该接口是 Cursor 非公开内部接口，字段变化时会明确降级，不伪造额度。

### SSH 终端能登录，PulseDock 失败

复制诊断，根据“DNS/路由/连接超时/主机指纹/认证”分类处理。在终端运行 `ssh -G <别名>` 和 `ssh -vvv <别名>`。确认不需要交互式密码，密钥已在 ssh-agent 中，跳板机/VPN 已连接。

### 设备显示“部分异常”

展开详情查看分层证据。`HTTP 401/403` 表示 Codex POST 端点可达，但远端 curl 没有登录凭据；这与“网络不通”不同。“端点未返回 HTTP 状态”、DNS/TLS/超时、缺少采集 marker 会明确降级。

### 声音无法播放

查看“连接中/缓冲中/播放异常”状态，点“重试”会重建当前音频项，而不是对失败的 player 简单 resume。电台可能因地区、codec、节目维护或临时过载不可用，可换一条音源。

### 时间线为空

新安装在没有异常和状态变化时可以较少。手动执行一次 AI 诊断、番茄钟完成或 SSH 刷新后应有事件。页面显示“存储错误”时复制具体路径和原因；不要只点“清空已恢复”来隐藏写入失败。

## 15. 本地数据与卸载

非秘密偏好保存在 UserDefaults，活跃度与时间线保存在 `~/Library/Application Support/PulseDock/`，凭据保存在 macOS Keychain 的 `com.pulsedock.monitor` PulseDock 项。

卸载应用只需删除 `PulseDock.app`。若同时需要清理数据：

1. 先在 PulseDock 中“清除统一凭据保险库”；
2. 完全退出；
3. 备份后再删除 `~/Library/Application Support/PulseDock/` 与 PulseDock 相关 UserDefaults。
