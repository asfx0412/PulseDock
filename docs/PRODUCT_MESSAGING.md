# PulseDock 产品定位与对外表达

本文是 README、Release、官网/落地页和对外内容的共同事实来源。它定义“该说什么、如何证明、什么不能说”；不替代版本更新日志。

## 一句话定位

**PulseDock 是面向 AI 开发者的 macOS 工作状态驾驶舱：用一个低干扰浮窗，把此刻影响工作的信号放在一起。**

它服务的不是“监控一切”，而是帮助个人开发者在编码、远程任务、额度与网络波动之间，快速决定下一步是否需要处理。

## 目标用户与场景

| 用户 | 高价值场景 | 先讲什么 |
|---|---|---|
| 使用 Codex 的独立开发者 | 编码中想知道额度、网络和当前专注状态 | 一眼掌握 + 本机只读 Codex 状态 |
| 使用远程机器/GPU 的 AI 开发者 | 跑任务期间要确认设备是否仍可达、GPU 是否正常 | 可选 SSH/GPU/Slurm 设备卡 + 本地诊断证据 |
| 在本机使用代理、多个 API 服务的人 | 调试服务时区分网络、配额和本地环境问题 | 低频诊断、Clash/Mihomo 与额度连接器按需接入 |

不面向团队考勤、网页内容分析、员工行为监控或云端统一运维。不要把“应用层活跃度”写成“追踪工作内容”或“分析页面”。

## 核心价值支柱

### 1. 一眼掌握：让状态服务于决策

首页表达：**“不用在终端、网页和设置之间来回切换，先看一眼，再决定要不要处理。”**

可验证事实：可收起浮窗、前台应用、工作状态、番茄钟、天气、AI 网络、额度和系统提示；暂时失败会显示状态并尽量保留最后成功结果。

### 2. AI 开发原生：连接器为实际工作流服务

首页表达：**“Codex、网络、远程 GPU 和专注节奏，不必各自占一个窗口。”**

可验证事实：本机 Codex `app-server` 只读状态；可选 Clash/Mihomo、SSH/GPU、Slurm、API 额度、诊断与时间线。必须写明“可选、按需配置”，不得暗示所有来源默认可用。

### 3. 本地优先：把权限和边界说在前面

首页表达：**“看状态，不看内容；存本机，不上传遥测。”**

可验证事实：活跃度只到前台应用层；不读窗口标题、网页、聊天、输入或文件；秘密由 Keychain 保存；时间线在本机；报告排除秘密。不得宣称“绝对安全”“零风险”或“无需任何权限”。

## 信息架构

首页只回答五个问题：它是什么、适合谁、为什么值得试、如何安装、有什么边界。详细配置放到使用文档，版本变化放到 Release/CHANGELOG，技术实现放到架构/测试文档。

推荐首屏顺序：一句话定位、三项核心优势、一张当前稳定版本且已脱敏的产品截图或 15 秒 GIF、三分钟安装、隐私边界与限制、文档与反馈入口。

## 对外表述规则

| 可以说 | 不能说 | 原因 |
|---|---|---|
| “在一个浮窗中查看当前工作状态” | “全方位监控你的电脑” | 实际能力有明确范围，后者制造隐私误解 |
| “读取本机 Codex 的只读状态” | “读取/管理你的 Codex 账号” | 不读取、导出或刷新登录 Token |
| “可选接入 SSH/GPU、Clash/Mihomo、API 额度” | “开箱即用支持所有设备和服务” | 需要用户显式配置，兼容性有边界 |
| “本地优先、秘密在 Keychain” | “绝对安全、永不泄露” | 安全承诺必须可审计且不能绝对化 |
| “安装包尚未公证，按说明确认来源后打开” | “绕过 macOS 安全限制” | 保留真实状态与用户知情权 |

## 版本与证据规则

- README 不手填“当前版本”、具体 ZIP 名或本版修复摘要；使用 Latest Release 链接和动态版本徽章。
- 一次发布只在 `CHANGELOG.md`、`outputs/PulseDock-<版本>发布说明.md` 和 GitHub Release 叙述版本变化。
- 截图必须来自当前稳定版本，且脱敏；若画面中含版本号，应与当前 Release 一致。过期截图移除或明确标注为功能示意，不能作为版本依据。
- 宣传内容只能使用已经发布并能在 README、Release、测试或源代码中核对的能力。

## 近期产品优化路线（需以用户反馈验证）

1. **首次 5 分钟成功：** 用最少配置展示浮窗、番茄钟和手动天气；将 Codex、设备、额度配置改成独立的渐进式引导。
2. **信号优先级：** 允许用户明确选择“现在最关心的三项”，并解释为何出现黄色/红色状态，避免信息过载。
3. **可信反馈闭环：** 为每个外部来源展示最后成功时间、错误类别、下次重试和隐私范围；以匿名且可选的用户反馈收集替代隐式遥测。
4. **发布成熟度：** 完成 Developer ID 签名与 Apple 公证，再把“首次打开”从排障步骤变成顺畅安装体验。

这些是产品方向，不是已发布功能；在写入 README、Release 或宣传素材前，必须完成设计、实现和验证。
