# PulseDock 发布节奏

- 合并代码不等于发布安装包。普通的小修复先进入 `main`，经过测试后与下一次计划版本一起发布。
- 影响核心功能、安全或造成持续干扰的问题可以立即发布热修复；热修复递增三段版本号的补丁位，例如 `6.16.5` → `6.16.6`。
- 每个公开版本只发布一次。不要覆盖已有标签、ZIP 或签名更新清单；独立版本便于用户判断更新、回退和核对问题。
- 发布前验证版本号、完整测试、App 构建、ZIP、签名清单与公开下载文件。已安装程序只提示比自身版本号更高的已验证版本，安装仍需用户确认。

版本号递增是修复记录，不要求每次代码提交都立即发布。紧急修复优先保证可追溯和可靠送达，而不是保持版本号不变。
