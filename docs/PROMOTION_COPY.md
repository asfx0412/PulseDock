### 正文（可直接发布）

写 AI 项目时，我经常在终端、Codex、远程 GPU、网络状态和番茄钟之间反复切换。真正打断我的不是信息少，而是关键信息太分散。

所以做了 PulseDock：一个可以收起的 macOS 浮窗。平时只看当前前台应用、专注计时、天气、AI 网络和额度；需要排查时再展开看 Codex 状态、SSH/GPU、Clash/Mihomo、时间线和诊断。

1. 它只记录前台应用层级，不读取窗口标题、网页、聊天、输入内容或文件；

适合 Apple Silicon + macOS 26 的 AI 开发者。Codex、远程设备和 API 额度都是按需配置，不会一上来索要一堆权限。

### 正文（可直接发布）

AI 开发的工作台，常常不是一个 IDE，而是一组分散的状态：模型额度、网络是否可达、远程 GPU 是否在跑、今天是否已经被频繁切换打断。

PulseDock 的出发点不是再做一个“大而全”的监控平台，而是为个人开发者提供一个可收起的 macOS 工作状态驾驶舱。平时，它只呈现当前前台应用、工作状态、番茄钟、天气、AI 网络和关键额度；只有需要处理问题时，才展开设备、诊断、时间线等细节。

我们把产品价值收敛在三点。

第一，一眼掌握。减少在终端、网页和设置之间的无效跳转，让状态帮助你决定“现在是否需要处理”。

第二，贴近 AI 开发工作流。PulseDock 可以读取本机 Codex 的只读状态，并按需接入 SSH/GPU、Slurm、Clash/Mihomo 和 API 额度。它们都是可选能力：不使用，就不配置。

第三，本地优先。应用活跃度只停留在前台应用层，不读取网页、聊天、窗口标题、输入内容或文件。秘密放在 macOS Keychain，时间线保存在本机，诊断报告会排除 API Key、密码和未脱敏命令。

当前版本面向 Apple Silicon 与 macOS 26。安装包尚未完成 Apple 公证，首次打开需要用户确认来源；我们把这项限制明确写在安装步骤中，而不是把它藏起来。

### 导语

开发环境中的状态信号往往散落在终端、网页和多个客户端中。PulseDock 是一个 Swift/macOS 项目，尝试用低干扰浮窗提供“现在值得处理什么”的答案，同时把隐私、凭据与发布验证作为一等约束。

### 正文大纲与首稿

#### 1. 要解决的不是监控，而是决策延迟

AI 开发者会同时面对配额、网络、远程任务、系统热状态和专注节奏。把所有内容塞进面板并不能降低认知负担；PulseDock 的策略是紧凑态只放高优先级信号，展开态才提供洞察、设备、诊断和时间线。

#### 2. 连接器设计：可选、只读、有边界

Codex 通过本机 `app-server` 的只读接口读取，不管理登录 Token；SSH/GPU 使用已有的 `~/.ssh/config` 与 ssh-agent，并以 `BatchMode=yes` 避免后台密码框；Clash/Mihomo 只连接本机兼容元数据、回环 Controller 或本机 Unix Socket。每种外部能力都要由用户显式配置。

#### 3. 隐私模型：应用层状态，而不是内容采集

前台活跃度只识别 macOS 应用层级，不读取窗口标题、网页、聊天、键盘输入或文件。API Key、Webhook 和 Controller Secret 进 macOS Keychain；活跃度和时间线保存在 `~/Library/Application Support/PulseDock/`。这比一句笼统的“保护隐私”更可审查。

#### 4. 发布与可验证性

每次发布使用 GitHub Release 分发 ZIP 和签名清单；构建会检查版本、arm64、代码签名和归档内容，清单再由客户端公钥反验。当前安装包尚未完成 Apple 公证，因此首次安装需要用户确认来源——这是当前限制，而不是可以略去的细节。

#### 5. 如何运行

项目面向 Apple Silicon + macOS 26。普通用户从 Release 下载 ZIP，拖入 Applications 后按 README 首次打开；开发者可执行 `./scripts/test.sh`、`./scripts/build.sh` 从源码构建。完整安装、配置和安全说明见项目 README。
